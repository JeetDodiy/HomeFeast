1. Project overview
HomeFeast is a responsive web platform where students, working professionals and
elderly people find verified home cooks and subscribe to daily, weekly or monthly tiffin
meals. Phase 1 is web only, built on a limited budget and a fixed timeline, and ends with
four deliverables: a working web app, an admin dashboard, PRD plus technical
documentation, and a deployment-ready build.

Solving each problem step by step
1. Cost: show monthly price divided by meals so users compare tiffins fairly; offer weekly
and monthly discounts.
2. Variety: let cooks publish a 7-day menu; show "today's menu" on the cook card.
3. Subscription: model a plan as cook + meal type + duration + days; the cook accepts or
rejects it.
4. Discovery: index cooks by city, area / pincode and service radius; sort by distance,
rating and price.
5. Coordination: status flow Pending → Accepted → Active → Paused / Cancelled /
Completed, with email and in-app alerts at each change.
6. Trust: admin approves each cook after document check (ID and food safety / FSSAI
details for India); only approved cooks appear in search.
7. Scale: every cook, menu and order carries a cityId , so a new city is data, not code.

10. Master prompt to build the website
Copy the prompt below into Claude, Cursor, v0 or another AI builder. For the best result,
build in stages: first send the whole prompt and ask for the project setup and database,

You are a senior full-stack engineer and UI/UX designer. Build a productionquality, deployment-ready web application called "HomeFeast – Homemade Tiffin
& Food Service Platform" for a software internship project.
## 1. PRODUCT CONTEXT
HomeFeast is a responsive web platform that connects users (students, working
professionals, elderly people living away from home) with verified home cooks
and tiffin providers offering fresh, hygienic, home-style meals on daily,
weekly or monthly subscriptions. It replaces manual coordination through
calls and WhatsApp and avoids expensive, repetitive restaurant food.
Phase 1 is web only. Out of scope: native mobile apps, AI meal
recommendations, cloud-kitchen integrations, online payments (use Cash / UPI
on delivery for now, but design the code so a payment gateway and wallet can
be added later).

- Backend: Node.js + Express.js (TypeScript), REST API under /api/v1,
Swagger/OpenAPI docs
- Database: PostgreSQL with Prisma ORM (include migrations and a seed script)
- Cache / rate limit: Redis (optional in dev, with in-memory fallback)
- Uploads: Cloudinary (or S3) for images and documents
